Otimização de Licenças Power BI via Auditoria de Logs em Capacidades Premium

Contexto & Problema

A empresa mantinha 12 capacidades Premium ativas e arcava simultaneamente com mais de 6.000 licenças pagas do Power BI Pro. Isso gerava um custo recorrente muito elevado. Como os relatórios publicados em workspaces alocados em capacidades Premium não exigem licença Pro para visualização (usuários com licença gratuita podem consumir normalmente), surgiu a oportunidade de reduzir licenças sem prejudicar ninguém.

O que eu fiz

Usando SQL nos logs de auditoria do tenant, filtrei os usuários que possuíam licença Pro e analisei todo o histórico de atividades. A lógica consistia em identificar quem consumia exclusivamente relatórios em capacidades Premium (evento ViewReport). Se o usuário tivesse realizado qualquer ação que dependesse de Pro (editar relatório, publicar, criar conjunto de dados ou acessar workspace não-premium), ele continuava com a licença Pro. Quem só visualizava relatórios em Premium foi marcado para downgrade (Free).

Geração da lista final auditada para downgrade para licença Free com zero interrupção, economizando cerca de R$ 500.000 para 2025.

query_auditoria_licencas.sql 
-- Consulta para identificar usuários Pro elegíveis para licença gratuita (Free)
-- Regra: Apenas usuários cujo histórico é 100% de visualização em capacidade Premium

WITH AtividadesAgrupadas AS (
    SELECT 
        u.UserEmail,
        u.Department,
        u.CurrentLicense,
        COUNT(a.ActivityId) AS TotalAtividades,
        
        -- Visualizações legítimas em workspaces que estão em capacidade Premium
        COUNT(CASE 
            WHEN a.ActivityType = 'ViewReport' AND w.IsPremiumCapacity = 1 
            THEN 1 
        END) AS ViewsEmPremium,
        
        -- Qualquer atividade que realmente exige Pro:
        -- Edição, criação, publicação ou consumo fora de Premium
        COUNT(CASE 
            WHEN a.ActivityType != 'ViewReport' 
              OR w.IsPremiumCapacity = 0 
            THEN 1 
        END) AS AtividadesQueExigemPro

    FROM Dim_Users u
    INNER JOIN Fact_AuditLog a ON u.UserEmail = a.UserEmail
    INNER JOIN Dim_Workspaces w ON a.WorkspaceId = w.WorkspaceId
    WHERE 
        u.CurrentLicense = 'Power BI Pro'
        AND a.ActivityDate >= DATEADD(month, -3, GETDATE())
    GROUP BY 
        u.UserEmail,
        u.Department,
        u.CurrentLicense
)
SELECT 
    UserEmail,
    Department,
    CurrentLicense,
    TotalAtividades,
    ViewsEmPremium,
    AtividadesQueExigemPro,
    'Elegível para Downgrade (Free)' AS Recomendacao
FROM AtividadesAgrupadas
WHERE 
    TotalAtividades > 0
    AND ViewsEmPremium > 0
    AND AtividadesQueExigemPro = 0 -- Se fez qualquer ação de autor/fora de premium, é excluído
ORDER BY 
    TotalAtividades DESC;

Sistema de Monitoramento do Tenant Power BI em Microsoft Fabric (Workspace Monitoring)

Contexto & Objetivo

Para viabilizar análises como a de otimização de licenças e ter visibilidade geral da saúde do tenant, criei um workspace chamado Monitoring no Microsoft Fabric. O objetivo era centralizar informações sobre atividades de usuários, inventário de workspaces, capacidades, rotinas de atualização de datasets, dataflows e status de gateways. O conceito foi inspirado no FUAM (Fabric Unified Activity Monitor), mas adaptado de forma direta e simplificada para a necessidade da operação.

Arquitetura da Solução

Construí notebooks em Python/PySpark no Fabric para fazer as requisições na API REST administrativa do Power BI, lidando com autenticação e paginação de dados. O retorno das APIs é salvo em tabelas Delta dentro de um Lakehouse. Toda a execução dos notebooks foi orquestrada por meio de um Data Pipeline agendado no Fabric, e os dados foram estruturados em um modelo dimensional (esquema estrela) para alimentar os relatórios de governança.

Arquitetura de Dados & Etapas de Construção
01
Mapeamento dos Endpoints das APIs REST

Identificação das APIs administrativas do Power BI: Activity Events, inventário de Workspaces, histórico de Refreshes e Clusters de Gateways.

02
Ingestão via Fabric Notebooks

Construção de rotinas com autenticação via Service Principal (Entra ID) e paginação com continuationToken para carregar lotes de telemetria.

03
Armazenamento Estruturado em Lakehouse Delta

Persistência dos dados brutos em tabelas Delta particionadas no Lakehouse, garantindo histórico perene e consultas de alta performance.

04
Orquestração em Data Pipelines

Agendamento de pipelines no Fabric para rodar os notebooks sequencialmente com tratamento de falhas e alertas.

05
Modelagem Dimensional & Observabilidade

Estruturação de um Star Schema para relatórios no Power BI, dando visibilidade da saúde do tenant para mais de 70.000 usuários ativos.

# Fabric Notebook: Extração de eventos de auditoria da API REST do Power BI
import requests
import json
from datetime import datetime, timedelta

# Autenticação via Service Principal (segredos armazenados com segurança)
token_url = f"https://login.microsoftonline.com/{TENANT_ID}/oauth2/v2.0/token"
payload = {
    "grant_type": "client_credentials",
    "client_id": CLIENT_ID,
    "client_secret": CLIENT_SECRET,
    "scope": "https://analysis.windows.net/powerbi/api/.default"
}
token = requests.post(token_url, data=payload).json().get("access_token")
headers = {"Authorization": f"Bearer {token}", "Content-Type": "application/json"}

# Extração paginada de eventos do dia anterior
data_auditoria = (datetime.now() - timedelta(days=1)).strftime("%Y-%m-%dT00:00:00.000Z")
url = f"https://api.powerbi.com/v1.0/myorg/admin/activityevents?startDateTime='{data_auditoria}'&endDateTime='{data_auditoria}'"

eventos = []
while url:
    res = requests.get(url, headers=headers).json()
    eventos.extend(res.get("activityEventEntities", []))
    continuation_token = res.get("continuationToken")
    url = f"https://api.powerbi.com/v1.0/myorg/admin/activityevents?continuationToken='{continuation_token}'" if continuation_token else None

# Gravação no Lakehouse em formato Delta
df = spark.read.json(sc.parallelize([json.dumps(e) for e in eventos]))
df.write.format("delta").mode("append").saveAsTable("Lakehouse_Monitoring.Fact_ActivityEvents")
