Otimização Inteligente de Licenças Power BI via Auditoria de Logs em Capacidades Premium

Auditoria avançada de telemetria sobre mais de 6.000 licenças pagas e 12 capacidades Premium, identificando padrões estritos de consumo para realizar downgrades seguros (Pro para Free) com zero interrupção operacional.

1. O Desafio de Custos

A organização mantinha 12 capacidades Premium dedicadas e arcava simultaneamente com +6.000 licenças Pro ativas. Isso gerava um custo de licenciamento anual exorbitante e redundante.

2. A Regra Arquitetural

Em workspaces hospedados em Capacidades Premium, consumidores de relatórios não precisam de licença Pro; uma licença Free (gratuita) é suficiente para visualizar e interagir com relatórios.

3. O Critério Estrito (SQL)

Um usuário só era elegível se 100% das suas atividades fossem ViewReport dentro de capacidades Premium. Qualquer atividade de edição, criação ou acesso a workspace compartilhado mantinha o usuário como Pro.

Lógica Validada em Produção
query_otimizacao_licencas_powerbi.sql 
-- =========================================================================
-- CASE VALE: Identificação de Usuários Pro Elegíveis para Downgrade (Free)
-- Regra: Usuário Pro cujo histórico tem EXCLUSIVAMENTE 'ViewReport' em Premium
-- =========================================================================

WITH UserAuditAggregated AS (
    SELECT 
        u.UserEmail,
        u.Department,
        u.CurrentLicense,
        COUNT(a.ActivityId) AS TotalActivities,
        
        -- Contagem de acessos válidos: visualização em capacidade Premium
        COUNT(CASE 
            WHEN a.ActivityType = 'ViewReport' AND w.IsPremiumCapacity = 1 
            THEN 1 
        END) AS PremiumViewCount,
        
        -- Contagem de atividades restritas que EXIGEM licença Pro:
        -- Edição, Criação, Publicação, Exportação ou qualquer ação em Workspace Não-Premium
        COUNT(CASE 
            WHEN a.ActivityType != 'ViewReport' 
              OR w.IsPremiumCapacity = 0 
            THEN 1 
        END) AS ProRequiredActivitiesCount

    FROM Dim_Users u
    INNER JOIN Fact_PowerBI_AuditLog a 
        ON u.UserEmail = a.UserEmail
    INNER JOIN Dim_Workspaces w 
        ON a.WorkspaceId = w.WorkspaceId
    WHERE 
        u.CurrentLicense = 'Power BI Pro'
        AND a.ActivityDate >= DATEADD(month, -3, GETDATE()) -- Janela de 90 dias de auditoria
    GROUP BY 
        u.UserEmail,
        u.Department,
        u.CurrentLicense
)
SELECT 
    UserEmail,
    Department,
    CurrentLicense,
    TotalActivities,
    PremiumViewCount,
    ProRequiredActivitiesCount,
    'ELEGIVEL_DOWNGRADE_FREE' AS StatusRecomendado,
    'Economia imediata de licença Pro sem impacto operacional' AS Justificativa
FROM UserAuditAggregated
WHERE 
    TotalActivities > 0
    -- O usuário visualizou relatórios em Premium...
    AND PremiumViewCount > 0 
    -- ...E JAMAIS realizou qualquer atividade que demande licença Pro!
    AND ProRequiredActivitiesCount = 0
ORDER BY 
    TotalActivities DESC;

Sistema de Telemetria e Governança do Tenant Power BI em Microsoft Fabric

Desenvolvimento de uma solução completa de auditoria e observabilidade empresarial no Microsoft Fabric (workspace "Monitoring"), inspirada conceitualmente em ferramentas como o FUAM (Fabric Unified Activity Monitor), porém simplificada e sob medida. Extração automatizada via REST APIs com Fabric Notebooks (PySpark), armazenamento em Lakehouse Delta, orquestração com Data Pipelines e modelagem dimensional para monitorar consumo, falhas de atualização e saúde de gateways.

1. Observabilidade do Tenant

Com dezenas de capacidades e milhares de artefatos distribuídos, a gestão do tenant demandava visibilidade centralizada sobre atividades de usuários, rotinas de refresh, dataflows e status de gateways.

2. Fabric Notebooks & APIs

Desenvolvimento de scripts Python/PySpark em Fabric Notebooks com paginação e autenticação OAuth2 para extrair dados brutos das Power BI Admin REST APIs e persistir em tabelas Delta no Lakehouse.

3. Orquestração & Modelagem

Orquestração agendada via Fabric Data Pipelines alimentando um Star Schema (fatos de atividades e histórico de refreshes conectadas a dimensões de workspaces e gateways) para relatórios no Power BI.

# =========================================================================
# MICROSOFT FABRIC NOTEBOOK: Ingestão de Telemetria de Atividades do Tenant
# Extração paginada da REST API 'admin/activityevents' para Lakehouse Delta
# =========================================================================

import requests
import json
from datetime import datetime, timedelta
from pyspark.sql import SparkSession
from pyspark.sql.types import StructType, StructField, StringType, IntegerType, TimestampType

# 1. Configuração de Autenticação Entra ID (Service Principal)
TENANT_ID = mssparkutils.credentials.getSecret("KeyVaultScope", "TenantId")
CLIENT_ID = mssparkutils.credentials.getSecret("KeyVaultScope", "ClientId")
CLIENT_SECRET = mssparkutils.credentials.getSecret("KeyVaultScope", "ClientSecret")

token_url = f"https://login.microsoftonline.com/{TENANT_ID}/oauth2/v2.0/token"
token_payload = {
    "grant_type": "client_credentials",
    "client_id": CLIENT_ID,
    "client_secret": CLIENT_SECRET,
    "scope": "https://analysis.windows.net/powerbi/api/.default"
}
token_response = requests.post(token_url, data=token_payload).json()
access_token = token_response.get("access_token")

headers = {
    "Authorization": f"Bearer {access_token}",
    "Content-Type": "application/json"
}

# 2. Extração de Eventos de Auditoria com Paginação (Continuation Token)
audit_date = (datetime.now() - timedelta(days=1)).strftime("%Y-%m-%dT00:00:00.000Z")
api_url = f"https://api.powerbi.com/v1.0/myorg/admin/activityevents?startDateTime='{audit_date}'&endDateTime='{audit_date}'"

all_events = []
while api_url:
    res = requests.get(api_url, headers=headers)
    if res.status_code == 200:
        data = res.json()
        activity_entities = data.get("activityEventEntities", [])
        all_events.extend(activity_entities)
        
        # Paginação via continuationToken da API do Power BI
        continuation_token = data.get("continuationToken")
        if continuation_token:
            api_url = f"https://api.powerbi.com/v1.0/myorg/admin/activityevents?continuationToken='{continuation_token}'"
        else:
            api_url = None
    else:
        raise Exception(f"Erro na extração da API Power BI: {res.status_code} - {res.text}")

print(f"Total de eventos extraídos para {audit_date}: {len(all_events)}")

# 3. Conversão para Spark DataFrame e Carga no Fabric Lakehouse (Delta Table)
